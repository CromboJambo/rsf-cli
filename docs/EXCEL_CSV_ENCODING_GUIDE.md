# Excel CSV Export Encoding Guide

## The Problem

Excel/Talend exports often use **UTF-16 encoding** with embedded newlines in quoted fields, which breaks standard CSV parsers like the Rust-based `rsf-cli` tool.

### Common Symptoms:
```
Error: Failed to read CSV record
Caused by: CSV error: found record with 5 fields, but previous record has 1 fields
```

This happens because Excel sometimes writes quoted headers like:
```csv
"Field1"\t"Field2"\r\n""\t"Field3"...   # Newline inside quotes!
```

## The Solution

Use the provided conversion scripts to handle these exports robustly.

### Quick Start

```bash
# Convert a single file
./scripts/convert-to-utf8.sh data/ToExcel_JobOrders.csv

# Or with custom output name
./scripts/convert-to-utf8.sh data/ToExcel_Joborders.csv data/my_clean_file.csv
```

### Python Script (Advanced)

For programmatic use:

```python
from scripts.convert_excel_csv import convert_excel_csv

output_path = convert_excel_csv(
    input_path="data/raw_export.csv",
    output_path="data/clean_output.csv"
)
print(f"Converted to UTF-8: {output_path}")
```

## How It Works

1. **Auto-detect encoding** using `chardet` library
2. **Fix embedded newlines** by merging split header fields
3. **Normalize line endings** (CRLF → LF)
4. **Validate field consistency** across all rows
5. **Write clean UTF-8 CSV** with proper quoting

## Usage Workflow

```bash
# 1. Get your Excel export (usually UTF-16)
cp /path/to/export.csv data/raw_export.csv

# 2. Convert to clean UTF-8
./scripts/convert-to-utf8.sh data/raw_export.csv

# 3. Now use with rsf-cli

```

## Troubleshooting

### Encoding Detection Failed
If `chardet` can't determine the encoding, the script falls back to UTF-16 detection.

### Still Getting Field Count Errors
Check if your file has:
- Extra blank lines at end → Script removes these automatically
- Mixed line endings (CRLF + LF) → Normalized by script
- Inconsistent delimiters → All converted to tabs

### Memory Issues with Large Files
For very large files (>10MB), consider processing in chunks or using `iconv` directly:
```bash
iconv -f UTF-16 -t UTF-8 input.csv > output.csv
```
